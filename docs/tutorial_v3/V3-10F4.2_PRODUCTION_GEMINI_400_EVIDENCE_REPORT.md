## Evidence

What this phase added to the evidence base:

1. **Production is `git HEAD`.** The failing planner is the committed build, so
   the failure is reproducible from source and is not an artifact of a stale or
   unknown deployment.
2. **The deployed request contract is unchanged.** Verified by downloading
   production and diffing, not by reading the working tree. The next planner
   attempt therefore reproduces the *same* Gemini request that produced the
   original 400, with only the error reporting different — which is the whole
   point of a diagnostic-only build.
3. **The speculative schema change is provably absent** from what is running.
4. **A latent trap was avoided.** Deploying the working tree would have added a
   pre-Gemini storage-path gate that can fail a session with `409` before the
   Gemini call, which could have produced a *different* failure and wasted the
   reproduction.

What is still missing is the single thing the phase exists to obtain: one real
planner attempt against version 2.
